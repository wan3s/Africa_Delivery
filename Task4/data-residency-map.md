# Data Residency Map — Africa Delivery

* **Дата:** 27.08.2026 · **Версия:** 1.0 · **Автор:** Solution Architect
* **Провайдеры:** AWS af-south-1 (Кейптаун) — основная платформа; локальные провайдеры в Лагосе и Найроби — хранилища идентификаторов
* **Юрисдикции:** Нигерия (NDPR / NDPA 2023), Кения (Data Protection Act 2019, KICA), ЮАР (POPIA)
* **Статус:** принято по консервативным допущениям до получения полного заключения юриста (ожидается 19.09.2026, вопрос Q4)

## 1. Стратегия в одном абзаце

Данные разделены на две части. **Идентификаторы субъекта** (телефон, имя, адрес доставки, геоточка, документы KYC) хранятся и обрабатываются в стране субъекта — за её пределы не выходят ни в открытом, ни в зашифрованном виде. **Операционные данные** (заказы, статусы, платёжные ссылки, аналитика) хранятся в af-south-1 и содержат вместо личных данных токен, выданный локальным хранилищем. Такое разделение делает вопрос «что именно считается персональными данными» вопросом конфигурации — перечня полей, уходящих в хранилище идентификаторов, — а не поводом переписывать систему после заключения юриста.

Шифрование применяется ко всем данным, но **не используется как основание для трансграничной передачи**: зашифрованные персональные данные остаются персональными.

## 2. Карта инфраструктуры

| Провайдер | Регион | Код | Роль | Чьи данные |
| --- | --- | --- | --- | --- |
| AWS | Africa (Cape Town) | af-south-1 | Основная платформа: приложение, операционная БД, объектное хранилище, наблюдаемость | Обезличенные операционные данные всех стран; персональные данные субъектов ЮАР |
| Локальный провайдер | Лагос, Нигерия | NG-LOS | Хранилище идентификаторов нигерийцев + резервные копии внутри страны | Персональные данные субъектов Нигерии |
| Локальный провайдер | Найроби, Кения | KE-NBO | Хранилище идентификаторов кенийцев + резервные копии внутри страны | Персональные данные субъектов Кении |
| CDN | Точки присутствия: Лагос, Найроби, Йоханнесбург | — | Кеш каталога и изображений | Данных, относящихся к субъектам, не содержит |

Регион af-south-1 физически расположен в ЮАР, поэтому персональные данные южноафриканцев локализованы по построению — отдельная площадка для ЮАР не требуется.

## 4. Что известно точно, а что остаётся предположением

| Известно из артефакта 3 | Принято как допущение до заключения |
| --- | --- |
| Прямой маркетинг без согласия в ЮАР запрещён; использование приобретённой базы 410 тыс. номеров проблематично в ЮАР и, вероятно, в Нигерии | Точный объём понятия «персональные данные» в каждом режиме |
| Персональные данные нигерийцев должны храниться в стране; маскирование может быть приемлемо в отдельных конфигурациях | Подпадают ли под регулирование псевдонимизированные данные заказов |
| Требуется регистрация в Комиссии, назначение сотрудника по защите данных и ежегодная аудиторская отчётность (Нигерия) | Допустимые сроки хранения по каждой категории |
| В Кении требования к платёжным данным строже, чем к общим клиентским | Допустима ли транзитная обработка вне страны при хранении внутри |
| Приём платежей — только через лицензированного провайдера | Является ли локализация в Кении обязательной или рекомендательной |

**Консервативное допущение.** Там, где норма допускает толкование, выбирается более строгое прочтение: идентифицирующие данные не покидают страну ни в каком виде, обработка ведётся там же, срок хранения — минимально необходимый. Ослабить режим после заключения юриста дёшево (объединение хранилищ, изменение перечня полей), ужесточить за две недели до запуска — невозможно.

## 5. Порядок действий при трансграничной передаче

Трансграничной передачей считается любой выход данных за пределы страны субъекта, включая передачу в зашифрованном виде.

1. **По умолчанию запрещено.** Идентифицирующие поля физически не покидают локальное хранилище: наружу отдаётся токен.
2. **Если сценарий требует передачи** (например, интеграция, работающая только с номером телефона) — сначала проверяется, можно ли обойтись токеном или обезличиванием.
3. **Если обойтись нельзя** — оформляется запись в реестре передач: какие поля, куда, зачем, на каком основании, срок хранения у получателя. Решение принимает сотрудник по защите данных совместно с внешним юристом.
4. **Передача без записи в реестре технически невозможна**: обращение к полям хранилища идентификаторов идёт только через его интерфейс, который журналирует запрос и его основание.
5. **Исключение — партнёры в той же юрисдикции.** Платёжные и логистические партнёры в Нигерии и Кении получают необходимый минимум данных (номер телефона, адрес доставки) в пределах страны — это не трансграничная передача.

## 6. Технические меры

| Мера | Как реализована |
| --- | --- |
| Токенизация | Единственный модуль доступа к идентификаторам; операционный код оперирует токенами и не имеет доступа к исходным полям |
| Шифрование хранения | Шифрование на уровне хранилища; ключи для нигерийского и кенийского хранилищ управляются в соответствующей стране и не выгружаются за её пределы |
| Шифрование канала | TLS 1.2+ для всех соединений, включая внутренние вызовы между регионами |
| Классификация полей | Каждое поле модели данных помечено категорией; попытка записать помеченное поле в операционную БД блокируется проверкой в CI |
| Маскирование | Телефоны, адреса и документы маскируются в логах и телеметрии на коллекторе |
| Ограничение доступа | Доступ к хранилищу идентификаторов — по ролям, каждое обращение журналируется с указанием основания |
| Сроки хранения | Автоматическая очистка по расписанию; до заключения юриста действует консервативная политика (NFR-CMP-04) |
| Проверка согласий | Отправка сообщения технически невозможна без записи согласия (FM-02) |

## 7. Контроль и отчётность

Ежеквартальный аудит: выгрузка перечня хранилищ и категорий данных, сверка с этой картой, проверка журнала трансграничных передач. Ежегодная отчётность в Комиссию по защите данных Нигерии (арт. 3). Ответственный — сотрудник по защите данных, назначение которого требуется NDPR и пока не выполнено (открытый организационный вопрос).

## Assumptions

- Конкретные локальные провайдеры в Лагосе и Найроби не выбраны: требуется проверка по критериям из `cloud-regions-comparison.md` и подтверждение возможности оплаты по счёту с отсрочкой 45 дней (арт. 6).
- Локализация персональных данных в Кении принята консервативно, хотя из артефакта 3 следует лишь «требования, близкие к локализации». Стоимость решения — около 400 USD в месяц; при ином заключении юриста хранилище объединяется с af-south-1.
- Ссылки на конкретные статьи законов и списки адекватных юрисдикций сознательно не приводятся: юрист прямо отказался давать эту конкретику до получения заключения (арт. 3), а решения, опирающиеся на непроверенные формулировки, создают ложную уверенность.
- Видеофиксация выдачи (артефакт 4, пункт 19) в MVP не реализуется: относится к особой категории данных, режим обработки не определён.
